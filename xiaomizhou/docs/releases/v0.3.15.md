# xiaomizhou v0.3.15

## NapCat 群转发与合并消息拆分

- 群对群转发原消息中的普通图片和图文，保留未转链消息的图文顺序，兼容公共 HTTP/HTTPS 图片地址和常见 CQ 字符串上报。
- 读取 NapCat / OneBot 合并记录并按顺序逐条发送，每条由当前登录 QQ 发送，不复用原聊天记录卡片和发送者身份。
- 转发规则新增「转发原消息图片」「拆开 QQ 合并消息」和发送间隔设置，旧规则自动迁移，两个开关默认开启。
- 拆开的商品分享对接现有京东、淘宝、拼多多转链；完整淘宝文案和口令参与解析，避免残留原始商品链接。
- QQ 回调队列、成功节点去重、持久化解析缓存和待重试任务；发送失败暂停后续节点，最多自动重试 3 次，重启后续发。
- 忽略自身 QQ 消息、禁止来源群向自身转发；加入节点数、嵌套和图片限制。

## 使用

升级后在「个人 QQ」接入 NapCat 正向 HTTP 与 HTTP POST 上报，再到「转发规则」填写来源群号和 `group:目标群号`，开启原图与拆分。

完整教程：[NapCat 群转发](https://github.com/najiuwanan511/xiaomizhou/blob/main/xiaomizhou/docs/napcat-forwarding.md)。

## 验证与边界

新增模拟 NapCat 的服务端集成测试，覆盖旧数据库迁移、图文顺序、合并消息解析、并发队列、原图与拆分开关、失败续发、进程重启后自动重试、缓存与去重、规则调整后节点定位和淘宝完整文案转链。未使用用户 QQ 账号发真实消息，接入后仍需核对实际 NapCat/QQ 图片与群发权限。

每份最多 50 条、3 层嵌套；暂不搬运语音、视频、文件和其他卡片。图片需是可访问的公共地址；网络超时且平台响应丢失时，重试仍可能重复。QQ 官方机器人不能替代 NapCat 做持续主动群推送。
