# NapCat 群对群转发

适用版本：小米粥 v0.3.15 及以后。支持普通文字、网页链接、图片、图文，以及将合并聊天记录拆开逐条发送。发送者是 NapCat 当前登录的 QQ 账号，建议给该账号设置“小米粥”昵称或群名片。

## 1. 连接 NapCat

先按 [NapCat 官方安装说明](https://napneko.github.io/guide/boot/Shell) 安装并登录 QQ。使用飞牛 Docker 时，NapCat 和小米粥需要互相访问；这不是小米粥 QQ 官方机器人页面的 AppID/AppSecret 接入。

在 NapCat WebUI 的网络配置中创建并启用：

| 配置 | 示例 | 用途 |
| --- | --- | --- |
| HTTP Server（正向 HTTP） | 监听 `0.0.0.0`，端口 `3000` | 小米粥调用发送和读取记录接口 |
| HTTP Server 的消息格式 | `array` | 保留文字、图片和合并消息段 |
| HTTP Server 的 Access Token | 自己设置的令牌 | 填入小米粥的 NapCat Access Token |
| HTTP Client（HTTP POST 上报） | 小米粥页面显示的完整回调 URL | NapCat 把收到的消息交给小米粥 |
| HTTP Client 的消息格式 | `array` | 推荐设置；也兼容常见 CQ 字符串 |

小米粥「个人 QQ」填写：

- **HTTP API 地址**：例如 `http://192.168.31.13:3000`，不填写 NapCat WebUI 地址或 `/send_group_msg` 路径。
- **NapCat Access Token**：与 HTTP Server 一致。
- 勾选「启用消息接收」，保存，点击「测试连接」。
- 复制该页面的回调 URL，填入 NapCat HTTP Client 的 URL，例如 `http://192.168.31.13:8090/api/qq/events?token=小米粥接入令牌`。

NapCat API Token 和回调 URL 内的小米粥接入令牌是两个不同的值。NapCat HTTP Client 的 token 通常用于签名，不代替 URL 内的小米粥令牌。不要公开回调 URL。

如果分开部署容器，要映射相应端口，或使用同一 Docker 网络的服务名。容器中的 `127.0.0.1` 只代表该容器。实际 NAS 端口以你的映射为准。

## 2. 配置转发规则

让 NapCat 登录的 QQ 加入来源群 A 和目标群 B，并能在目标群发言。在小米粥「转发规则」中填写：

| 字段 | 填法 |
| --- | --- |
| 来源平台 | 个人 QQ |
| 来源会话 ID | 群 A 的普通群号，如 `123456789` |
| 目标平台 | 个人 QQ |
| 目标会话 | `group:987654321`，冒号后是群 B 群号 |
| 匹配范围 | 全部文字和图片 |
| 转发原消息图片 | 开启 |
| 拆开 QQ 合并消息，逐条发送 | 开启 |
| QQ 发送间隔 | 默认 `1000` 毫秒，可设 `500–10000` |
| 启用规则 | 开启 |

不要选「QQ 官方机器人」作为自动群搬运目标。腾讯官方机器人主动推送已停止提供：[腾讯说明](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)。

「仅含网页链接」会逐条检查拆开的内容，纯图片和没有链接的文字不会发送。关闭拆分后忽略合并记录正文，不发送原聊天记录卡片；消息中记录外的普通文字和图片仍可转发。

## 3. 发送效果与返利

- 普通图文保留文字与图片的排列顺序，重新由当前 QQ 账号发送。
- 合并记录按节点顺序拆开：一条图文仍是一条图文，纯图片单独发送。不会复制原发送者的身份，也不会创建新的合并记录。
- 开启「返利转链 → 消息自动转链」后，拆开的京东、淘宝、拼多多商品分享也会转链。单条淘宝分享的完整文案和口令会一起用于解析。
- 转链后发修改后的文案，并附带允许发送的图片；此时文字在前、图片在后。接口商品图片由返利页面的「附带商品图片」控制，原图由转发规则的图片开关控制。
- 商品转链失败时阻止该条原商品链接转发，写入运行日志并安排重试。

## 4. 队列与限制

- QQ 回调按接收顺序排队，避免两份记录的节点交叉发送；每个目标有发送间隔。
- 每份记录最多 50 条可发送内容、3 层合并嵌套、10 个外部记录引用。单条最多 4000 字、10 张图片；超出限制会报错，不悄悄截断合并记录。自动转链每份最多 10 个不同商品链接。
- 支持公共 HTTP/HTTPS 图片地址。文件路径、base64、私有 IP 等不作为转发图片来源。图片能否实际发送仍取决于 QQ 地址是否有效、NapCat 是否能读取。
- 语音、视频、文件、@、回复引用、表情和其他卡片暂不搬运。QQ 里的链接分享段会转换为标题及 URL 文本。
- 单条发送失败会暂停该批次的后续内容；小米粥自动在约 30、60、120 秒后重试，最多 3 次。不依赖 NapCat 是否重新上报。已确认成功的节点会跳过；解析结果和待重试任务保存在数据库，重启后继续。
- 转发规则中屏蔽向来源群自身发送，接收时忽略当前 QQ 账号自己的消息。这能防止单个小米粥账号的双向转发循环；多个其他机器人互相搬运仍需避免形成循环。
- 平台已收到消息但响应丢失时无法判断实际结果，网络超时后重试仍有重复风险；这是发送接口未提供幂等键的限制。

## 5. 验收与排错

用另一账号在 A 群依次发送普通文字、网址、纯图片、图文、三条内容的合并记录，检查 B 群是否按顺序显示。首次测试只建一条 A → B 规则，确认后再扩展。

| 现象 | 检查 |
| --- | --- |
| 测试连接失败 | NapCat 正向 HTTP 地址、端口映射、Access Token |
| 能连接但收不到群消息 | HTTP Client 是否启用、回调 URL 是否完整、两个容器是否能互访 |
| 文字正常但没有原图 | 转发规则图片开关、是否选择了仅链接、图片 URL 是否可访问 |
| 合并记录没有拆开 | 拆分开关、NapCat 消息格式、`get_forward_msg` 错误与记录是否失效 |
| 中途停下 | 小米粥运行日志与 NapCat 日志、QQ 禁言/风控、图片读取错误、重试是否用尽 |

协议参考：[NapCat API](https://napneko.github.io/onebot/api)、[OneBot 消息段](https://github.com/botuniverse/onebot-11/blob/master/message/segment.md)。

## 关键词拦截与文字／链接替换（v0.3.16）

每条转发规则可以保存自己的关键词和替换列表；不会改变其他规则。编辑规则时展开「关键词拦截与内容替换」：

### 关键词拦截

每行一个禁止关键词，例如：

```text
广告
禁止外传
spam.example
```

文案包含任意一个关键词，就跳过该条文字及其附带图片。合并记录中的其他条仍会继续发送。最多 50 个关键词，每个最多 100 字；默认忽略英文大小写，匹配时统一全角字符。关键词只检查文字，不识别图片中的文字。

原文会先检查一次，返利转链及内容替换后的最终文案再检查一次。即使设置「广告 → 留空」删除文字，原文命中「广告」的消息也不会转发。

### 内容替换

点击「添加替换」，填写原文字或完整链接，以及替换后的内容。例如：

| 原文字或链接 | 替换为 | 效果 |
| --- | --- | --- |
| 原群名称 | 小米粥 | 更换文案名称 |
| `https://old.example/a` | `https://new.example/my-link` | 更换匹配的链接 |
| 加群领取更多优惠 | 留空 | 删除这段文字 |

替换区分大小写，按列表顺序替换所有匹配的字面文本。`.*` 等字符按普通文字处理；替换内容中的 `$&` 也作为普通文字。可以「上移」「下移」调整先后顺序，最多 20 条。原文最多 500 字，替换内容最多 1000 字，允许填写多行文案。

处理顺序：**原文关键词检查 → 来源范围匹配 → 返利转链 → 文字／链接替换 → 最终关键词检查 → 发送**。

开启自动转链时，替换针对转链后的文案与实际推广地址；原商品网址可能已被替换为推广网址，此时填写原网址不会命中。若需要直接替换原网址，可以关闭消息自动转链。规则的「仅含网页链接」按来源文案判断。

删除全部文字后，若图片开关允许且消息带图，会发送图片；没有文字或图片则跳过。替换后超过 4000 字也会拦截，原因可在预览和运行日志中查看。

### 预览

在「测试文案」粘贴消息，点击「预览处理结果」，无需先保存。结果显示是否允许、命中的关键词、替换次数和处理后的文字。

预览不发 QQ 消息，也不调用返利或 AI 接口；若开启自动转链，请用转链后的文案测试替换。勾选「这条消息还带有图片」可检查文字删除后的结果，预览同时考虑规则的原图开关。

这些设置控制本条自动转发规则，插件自行生成的转发动作不使用这条规则的内容配置。旧规则升级后默认没有关键词和替换项，需自行填写并保存。
